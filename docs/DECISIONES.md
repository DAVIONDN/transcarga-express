# Decisiones de diseño — TransCarga Express

Documento de decisiones del MVP académico **TransCarga Express** (Django 5.2.18 + SQLite, ejecución local en Windows). Cada decisión está anclada en el código realmente implementado: la columna «Implementación» indica el archivo o módulo donde vive la regla, y ese archivo es la fuente de verdad.

## Requisitos proporcionados

Resumen del enunciado recibido, sin reinterpretarlo:

| Aspecto | Requisito proporcionado |
| --- | --- |
| Alcance funcional | Registrar transportistas con su vehículo y documentación, clasificarlos por nivel de carga, controlar advertencias y estados; registrar empresas clientes; publicar ofertas de carga; asignar un transportista a una oferta; panel de inicio con el resumen del sistema. |
| Stack obligatorio | Django (5.2 LTS) con plantillas del lado del servidor, base de datos SQLite, interfaz web en español, ejecución local. Sin React/Node, sin API REST, sin Docker, sin microservicios y sin bases de datos externas. |
| Reglas del negocio | Reglas numeradas R1–R14 del enunciado (documentación obligatoria, nivel derivado de la capacidad, certificación de carga peligrosa, estados, una asignación por oferta, una asignación activa por transportista, límite de advertencias, historial protegido, elegibilidad, validación en el servidor y acceso autenticado). |
| Validación | Toda validación es del lado del servidor (formularios y modelos); la interfaz solo presenta la información. |
| Moneda e idioma | Soles peruanos (S/), español de Perú, zona horaria `America/Lima`. |
| Referencia de entorno | Python 3.12 como versión de referencia del enunciado (ver decisión D1). |

### D1 en detalle: runtime Python 3.13.5 en lugar de 3.12

- **Motivo:** el equipo de desarrollo no tiene Python 3.12 instalado. El entorno virtual del proyecto se creó con el Python disponible en la máquina, 3.13.5, que es el runtime efectivo verificado en `.venv/pyvenv.cfg`.
- **Estado de Python 3.12:** la rama 3.12 está en **fase de solo seguridad**: ya no recibe correcciones de errores ni mejoras, únicamente parches de seguridad. Por eso **su último instalador oficial para Windows es 3.12.10**; las versiones posteriores de esa rama se publican solo como código fuente, sin instaladores binarios para Windows.
- **Compatibilidad con Django:** Django 5.2.18 declara `requires_python >=3.10` y la rama 5.2 soporta oficialmente Python 3.10, 3.11, 3.12, 3.13 y 3.14. Es decir, **3.13.5 está soportado** por la versión de Django fijada en `requirements.txt`, y 3.12 también lo estaba.
- **Por qué la desviación es compatible:** el proyecto no usa características exclusivas de una versión concreta de Python ni dependencias que exijan 3.12; solo Django 5.2.18 y Pillow 12.3.0. La totalidad de las pruebas se ejecuta sin cambios en 3.13.5.
- **Por qué es reversible:** basta con recrear el entorno virtual con Python 3.12 (`.venv`), reinstalar `requirements.txt` y volver a ejecutar `manage.py migrate` y las pruebas. No hay migraciones ni datos que dependan de la versión de Python, por lo que el regreso a 3.12 no requiere cambios de código.

## Aclaración sobre importes

No se inventaron **comisiones, penalidades ni importes** de ningún tipo. La única cifra monetaria del sistema es la **remuneración de la oferta** (`ofertas/models.py`), expresada en soles y validada como mayor que cero. Cualquier cobro por intermediación, penalidad por anulación o liquidación de pagos queda explícitamente fuera del MVP y figura únicamente como decisión pendiente (P3) o como alcance excluido en `docs/LIMITACIONES.md`.
